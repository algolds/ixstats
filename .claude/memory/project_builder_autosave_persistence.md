Country builder/editor state lives in `useBuilderState.ts` (`src/app/builder/hooks/`, ~1800 lines).
Three persistence layers (all "for all users"):

1. **localStorage** (both modes, 500ms debounce) — keys `builder_state` (create) / `builder_state_{countryId}` (edit). Per-browser; sessionStorage fallback; `beforeunload` sync save.
2. **Edit mode → Country row** (1500ms debounce) via `api.countries.updateCountry`. This is the real server persistence for existing countries.
3. **Create mode → `BuilderDraft` table** (June 2026) — per-user (`userId @unique`, Clerk id) JSON blob via `api.builderDraft` router (`get`/`save`/`clear`, all `protectedProcedure` = every authed user, no role/country gate). 2.5s debounce. Gives create-mode builds cross-session/cross-device persistence.
   - Coordination refs in the hook: `localHadDataRef` (on-device draft wins over server), `serverRestoreDoneRef` (gate server-save so empty initial state never clobbers a good draft). Only restores server draft when localStorage was empty + no in-progress data.
   - Cleared on successful create in `AtomicBuilderPage.tsx createCountryMutation.onSuccess` (else a completed build resurrects on next `/builder`).

**Round-2 builder bugs (fixed June 2026):**
- **Save button dead (edit mode):** removing `mode="wait"` from BuilderRouter's `AnimatePresence` (to fix Foundation-blank) let two `AtomicBuilderPage` instances overlap during section transitions; the outgoing one's cleanup `unregisterSubmit()` nulled the incoming one's `submitRef`. Fix: `unregisterSubmit(fn?)` in `BuilderStateContext` now no-ops if `submitRef.current !== fn`; `AtomicBuilderPage` passes its handler on cleanup. Also fixed `createCountryMutation?.isLoading` → `isPending` (react-query v5).
- **Edits reset for normal users (edit mode):** the edit-mode localStorage restore effect in `useBuilderState.ts` (~line 595) re-ran whenever `isLoadingCountry` flipped, merging stale localStorage back over freshly-loaded DB data; autosave then synced the stale data. Fix: one-shot `editRestoreDone` ref so it restores once.
- **Foundation blank on back (create mode):** `StepRenderer` `return null` when step↔section desync. Root: `popstate` (browser back) only set `activeSection`, not `builderState.step`. Fixes: (a) `popstate` handler now also syncs `builderState.step = sectionToLegacyStep(section)`; (b) `StepRenderer` final fallback renders `FoundationStep` (create) / `NationalIdentitySection` (edit) instead of `null` — never blank. NOTE edit-mode steps exclude `foundation` (`getStepsForMode`), so the blank was create-mode.

**Round-3: "one save/state" consolidation (June 2026, v2).** Users still reported lost edits. Root cause = multiple competing WRITE channels + a clobbering RESTORE. In the Economics section THREE writers raced the unified `updateCountry`: (a) `useEconomyBuilderAutoSync`→`economics.autoSaveEconomyBuilder` (flat `country.update`, shows OPTIMISTIC "Saved ✓" before server confirms — the smoking gun; in create mode `countryId` falls back to the template `selectedCountry.countryCode`, so it FORBIDDEN/not-found-fails after flashing Saved), (b) `useEconomyBuilderSync`→`syncEconomyWithTax` (fiscalSystem upsert, racing updateCountry's fiscalSystem). `EconomyBuilderPage` is ONLY rendered inside the builder (StepRenderer), where `builderContext` (`useBuilderContextOptional`) already feeds every edit back into builderState → updateCountry. Fixes:
- **Single writer:** gated both side-channels on `!builderContext` (EconomyBuilderPage:~488 `useEconomyBuilderAutoSync enabled: !!countryId && !builderContext`; added `enabled` prop to `useEconomyBuilderSync`, passed `!builderContext`, early-return in its sync effect). Standalone use still works.
- **localStorage = crash-recovery only (edit mode):** `useBuilderState` Effect 2 (~line 622) now only restores `builder_state_{countryId}` when its timestamp is strictly newer than `existingCountry.updatedAt`; else it discards the stale local copy (was unconditionally merging stale local over fresh DB once, then autosync pushed stale back). ponytail ceiling: client/server clock skew can rarely drop genuine unsaved local edits.
- **governmentComponents empty-array wipe:** updateCountry payload sent `|| []`; server treats a present array as authoritative (deleteMany→recreate), so `[]` on transient state wiped DB components. Now sends `undefined` (skip) when empty. ponytail ceiling: "user cleared ALL components" not persisted via autosave.
- **Deleted dead procs:** `government.autosave` + `taxSystem.autosave` (zero client callers). **Secured** `policies.savePolicySelections` (was unguarded write — any authed user could create policies for any country; dead client-side via useGovernmentSpending but reachable over tRPC) with owner/admin gate.
- Still-dead-but-harmless to clean later: `EconomyIntegrationService.syncWithGovernmentComponents/syncWithTaxSystem` methods (no callers), `useGovernmentSpending.savePolicySelections` action (instantiated, never invoked).

**Round-4: "edit one thing, everything resets" + partial-save audit (June 2026, v2).**
- LIVE editor tree (edit mode = `/mycountry/editor` → `BuilderRouter mode=edit` → ONE `BuilderStateProvider`/useBuilderState): StepRenderer renders `FoundationStep`, `NationalIdentitySection`, `GovernmentStep` (+`GovernmentSpendingSection`, `GovernmentBuilder`, `AtomicComponentSelector`), `EconomyBuilderPage`, `BuilderPreviewStep`. ⚠️ Most `src/app/builder/sections/*` files (FiscalSystemSection, CoreIndicatorsSection, GovernmentStructureSection, DemographicsSection, LaborEmploymentSection) are NOT live — only `GovernmentSpendingSection` is. Don't fix those; they're dead.
- **"Everything resets" root cause (FIXED):** circular write-back through `economyIntegrationService`. `EconomyBuilderPage`/`useEconomyBuilderSync` subscribes to the singleton service; `service.updateEconomicComponents()` REGENERATES `economyBuilder` from atomic components and notifies → subscription pushed it back via `onPersistEconomyBuilder` → `setBuilderState(economyBuilderState)`, clobbering the user's detailed economy config whenever components changed. Fix: gated the subscription write-back on `enabledRef` (= `!builderContext`); inside the unified builder the service is now DISPLAY-ONLY, builderState written only by direct user edits. (`useBuilderState.updateEconomicInputs` and `useNationalIdentityState.handleIdentityChange` were already correct — both merge off `prev`/`inputsRef.current`.)
- **National identity 15s autosync DISABLED** (`useNationalIdentityState`→`useNationalIdentityAutoSync enabled:false`): builder-only parallel partial-write side-channel; updateCountry (1.5s) already persists identity. Same class as the economy side-channels disabled in round-3.
- **Remaining partial-save cause = `updateCountry`/`createCountry` write incompleteness (FIXED June 2026):** Verifications were run against the Prisma schema models, and missing writes were added inside the update and create transactions in `update.ts` and `create.ts`:
  - `taxSystemData.taxExemptions[]` (recreated) and `taxSystemData.deductions` (recreated, indexed by category) are successfully saved.
  - `governmentStructure.budgetAllocations[]` (dynamically resolved to DB department IDs) and `revenueSources[]` are fully persisted.
  - `economyBuilderState` now maps and updates/upserts detailed metrics inside `EconomicProfile`, `LaborMarket`, and `Demographics` (gdpGrowthVolatility, economicComplexity, innovationIndex, competitivenessRank, sector breakdowns, employment shares, wage details, age and regional distributions, dependency ratios, birth/death/migration rates).
  - Direct fields `demographics.regions[]`, `incomeWealth.economicClasses[]`, and `governmentSpending.spendingCategories[]` are fully stringified and persisted.
  - `giniIndex` vs `incomeInequalityGini` fallback is implemented: a client-sent `giniIndex` (0–100) is scaled by `/ 100` and saved to `incomeInequalityGini` (0–1).
  - `flagExtractedColors` was audited and confirmed as client-only/unmapped in Prisma schema, so it is safely bypassed.

**Round-5: LOAD-side completeness + autosave UI centralization (June 2026, v2).** Round-4 made the SAVE (`updateCountry`) write everything (committed in `74b766ea`), but the editor still showed defaults on re-entry because the LOAD path didn't read it all back. The editor loads via 3 queries in `useBuilderState` Effect 1: `countries.getByIdAtTime` (only includes `nationalIdentity` — kept lean, 14 hot-path callers), `government.getByCountryId` (full: departments/budgetAllocations/revenueSources ✓), `taxSystem.getByCountryId` (transforms DB→`TaxBuilderState` incl categories/brackets/exemptions/deductions ✓). The gaps were: `governmentComponents` (Effect 1 hardcoded `[]` w/ TODO), `economyBuilderState` (`null`), demographics detail (regions/ageDistribution/educationLevels), `incomeWealth.economicClasses`, `governmentSpending.spendingCategories` — none fetched. Fixes:
- NEW owner-gated query `countries.getEditorRelations` (in `routers/countries/economy.ts`, spread via `index.ts`) returns demographics, incomeDistribution, governmentBudget, economicProfile, governmentComponents, economicComponents. useBuilderState adds it as a 4th edit-mode query; `relationsLoading` folded into `isLoadingCountry` so Effect 1 waits; `editorRelations` added to Effect 1 deps.
- Effect 1 now hydrates all 5: parses the JSON-string columns, maps `governmentComponents`→`ComponentType[]`, reconstructs `economyBuilderState` from `economicComponents` + parsed `economicProfile.sectorBreakdown`.
- **Centralized autosave UI** (per user req "remove component-specific autosave dialogs"): removed the "Auto-save pending/enabled/Autosaved!/Last saved" block + props from `EconomyBuilderHeader`, and the "Saving…/Saved/Pending" `renderAutosaveStatus` + `registerAutoSync("nationalIdentity")` from `NationalIdentitySection`. Save status now ONLY in the Dynamic Island (`BuilderDIPlugin`, round-3) + global `updateCountry` autosave. localStorage backup (500ms debounce + `beforeunload` flush + timestamp-guarded crash-recovery restore) confirmed intact.

**The bug that broke autosave (fixed June 2026):** the editor's autosync registry fires `economics.sync*` + fiscal/profile/config/builder mutations. All 11 checked `ctx.user?.countryId !== countryId` with NO admin/owner bypass and on possibly-stale cached `ctx.user` → flooded "Cannot access other countries' economic data" FORBIDDEN, so saves silently failed while the main `updateCountry` (fresh DB lookup + admin bypass) succeeded. Fixed with shared `assertCountryAccess` helper in `src/server/api/routers/economics/_ownership.ts` (fast path → admin/owner/system-owner bypass → fresh `user.findUnique` fallback). Same pattern added to `taxSystem/crud.ts` as `assertTaxAccess` (+ country-existence check to stop FK-constraint floods, + `update` now upserts a base row so it can't throw "TaxSystem not found").
