Onoma = client-side Markov name generator at `/labs/onoma` (commit 4100938a, branch v2).
Engine `src/lib/onoma/`, hook `useOnomaGenerator`, router `onoma.ts`, UI `OnomaRouter` + sections.

**Audit fixes shipped (June 2026):**
- The 4 `src/lib/onoma/data/*` modules (fantasy/species/group/tavern) are GENERATED by
  `scripts/extract-onoma-data.ts` from the original repo `github.com/algolds/onoma`, AND were
  silently excluded by a blanket `data/` rule in `.gitignore` → never committed → build broke on
  any fresh machine. Fixed by re-extracting + adding `!src/lib/onoma/data/` negation. Re-extract:
  clone onoma repo, sed the jxsig paths in extract-onoma-data.ts, `bunx tsx`.
- Markov dedup was a suffix-trie matching ANY substring of training data (over-rejected + O(L²)
  memory) → replaced with exact-match `Set<string>`. This is the key scaling fix for big corpora.
- Hook bugs: `api.onoma.logActivity` → `logGeneration`; `mapCategoryForTraining` returned
  geography/military not in `getTrainingData` enum → remapped to country|city|province|person.

**Bolster plan:** `plans/051-onoma-corpus-bolster.md`. Train on full IxWiki (direct MariaDB SQL) +
iiwiki/althistory (action API, one-time manual build). Spine = heavy work OFFLINE (extract→clean→
classify→compact dicts), light work in BROWSER (existing Markov trains on a few-KB dict). Frontend
organized by name CATEGORY only (per-nation clutters); backend orthographic classifier
auto-sorts each name into a real-world CULTURE bucket (pure-TS, no ML dep). See [[feedback_plans_dir]].

**Phase 2+3 DONE (June 2026):** corpus = 34,373 raw → **28,424 clean** (person 10.3k, country 7.5k,
org 7.1k, city 3.4k, province 30). Cleaner `src/lib/onoma/corpus/clean.ts` (pure, jest-tested):
strips disambig/quotes/gov-prefixes/regnal, KEEPS intra-word apostrophes. Classifier
`src/lib/onoma/corpus/culture-classifier.ts` = char bigram+trigram Naive-Bayes trained at module
load from existing `CULTURAL_PROFILES` (7 cultures, no ML dep), MIN_MARGIN=0.08, `classifyCulture()`.
On real corpus: 58% single culture, 42% **compound A+B** (top-2 within margin → `latin+slavic`
etc.), ~0% true-mixed. Compound idea (user's) resolved the old 40% "mixed"; adding new single
cultures (greek/french/etc. seeds) was measured useless (<1.4%, noise) and deleted.
`classifyCulture`→{culture,compound,components,confidence}; `rankCultures` exposes full ranking.
Top-6 compound subgroups: celtic+germanic, celtic+latin, latin+slavic, germanic+slavic,
germanic+latin, arabic+austronesian.
