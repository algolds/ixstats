# tRPC Router Overview

**Last updated:** September 2026

Routers live under `src/server/api/routers` and expose the typed API surface for IxStats. `src/server/api/root.ts` registers **<!-- BEGIN_DOCS:COUNT:routers -->76<!-- END_DOCS:COUNT:routers --> routers** with **<!-- BEGIN_DOCS:COUNT:procedures -->973<!-- END_DOCS:COUNT:procedures --> procedures** (per-router counts: [`docs/reference/api-complete.md`](../../../../docs/reference/api-complete.md), regenerated by `bun run docs:sync`; plan 312 removed ~500 zero-caller procedures). Many routers are split into subdirectory modules (e.g. geo, diplomacy, countries, government, wikios, onoma, thinkpages, security, vault). All routers are registered in `src/server/api/root.ts`.

## Request Flow
1. Client calls `api.<router>.<procedure>` generated in `src/trpc/react.tsx`
2. Request hits the Next.js handler (`src/app/api/trpc/[trpc]/route.ts`)
3. `createTRPCContext` (in `src/server/api/trpc/context.ts`) attaches Prisma, Clerk auth, the DB user, play-as impersonation, and the rate-limit identity
4. Middleware runs (`src/server/api/trpc/middleware.ts`: timing, auth, country-owner/admin checks, rate limiting, realm-aware caching, user logging, error formatting)
5. Router procedure executes business logic and returns serialised data via SuperJSON

## Common Middleware & Helpers
- **Auth & User Provisioning** – `getAuth` + `verifyToken` ensure Clerk users are mapped to database records (created on first sight unless `DATABASE_READONLY`)
- **Procedure builders** – `src/server/api/trpc/procedures.ts` (`publicProcedure`, `protectedProcedure`, `countryOwnerProcedure`, `adminProcedure`, cached and rate-limited variants)
- **Rate Limiting** – `~/lib/cache/rate-limiter`
- **User Activity Logging** – `~/lib/logging/user-middleware`
- **Error Logging** – `~/lib/logging/error-logger`

## Recent Changes
- **`realms`** router added with Realms Phase 1 (merged 2026-09-29) — realm admin, realm lookup, and nation claims; logic in `src/server/modules/realms/`.
- **Plan 312** deleted router residue and ~500 zero-caller procedures (including the former `mycountry.getNewsFeed` and `government.recalculateEffects`).
- **`thinkpages`** procedures `getFeed`, `getPost`, and `getPostsByClerkUserId` remain available (rate-limited public) — paginated feed, single post with replies/reactions, and per-user post listing.

## Subdirectory Routers
Some domains are split into multiple files under a subdirectory with an `index.ts` barrel:

- **`geo/`** — core/, features/, editor/, admin/ (+ admin/cities), sovereignty.ts, wiki.ts — each registered as its own top-level router
- **`diplomacy/`** — core/, embassies/, cultural/, policies/ — each registered as its own top-level router
- **`intelligence/`** — index.ts + templates.ts
- **`countries/`** — list, economy, identity, flags, wiki, atomic, and `management/` (a procedure-bag spread into the parent)
- **`wikios/`** — 11 sub-routers recombined with `mergeRouters`

## Adding a Router
1. Create `<name>.ts` under `src/server/api/routers` (or in a subdirectory with `index.ts`)
2. Export `createTRPCRouter({ ... })`
3. Register the router in `src/server/api/root.ts`
4. Regenerate the client if needed (the project uses dynamic type inference; no manual generation step)
5. Run `bun run docs:sync` to regenerate `docs/reference/api-complete.md`, and document new procedures in the relevant system guides

## Best Practices
- Prefer descriptive procedure names (`getLeaderboards`, `updateMissionStatus`)
- Validate all inputs with Zod schemas
- Restrict sensitive operations with `protectedProcedure` / role checks
- Reuse utilities from `src/lib`, `src/server/shared`, and `src/server/modules` rather than duplicating logic (no cross-router imports — `bun run audit:arch`)
- Keep each router file under 700 lines; split with `scripts/split-router-template.ts`
- Ensure new procedures have tests under `src/tests/server/api/` where feasible
