# IxStats Codebase Audit — June 2026

**Branch:** `v2` · **Stack:** Next.js 16.2.6, React 19.2.6, tRPC 11.17, Prisma 6.19 (PostgreSQL/PostGIS)
**Scope:** Full audit — performance, dead/bloated/deprecated/unused code, deployment infrastructure.
**Codebase size at audit:** ~786k LOC across ~2,434 source files (1,530 `.tsx`, 904 `.ts`), 35MB `src/`.

This document records findings and tracks remediation. IDs (D#/B#/F#) are referenced by the remediation commits. Line numbers are approximate and re-confirmed at edit time.

---

## 1. IxWorld Deploy Script (`scripts/deploy-ixworld.sh`) — HIGHEST PRIORITY

| # | Severity | Finding | Status |
|---|----------|---------|--------|
| D1 | **CRITICAL** | **Build-output clobbering.** Script `cd`s into `IXSTATS_DIR`, runs `rm -rf .next`, then `bunx next build` with `BASE_PATH=""` / `NEXT_PUBLIC_BASE_PATH=""` / `NEXT_PUBLIC_IXWORLD_STANDALONE=true`. `start-production.sh` serves IxStats prod via `next start` from that **same** `.next` (`exec node node_modules/.bin/next start`, line 115). Every IxWorld deploy overwrites the live IxStats production build with an empty-base-path / standalone build; IxStats prod (port 3550, base path `/projects/ixstates`) is broken until manually rebuilt. | fixed |
| D2 | HIGH | **Header comment ≠ behavior.** Header claims "Atomic-style update (no rm -rf)" and "graceful PM2 reload"; code does `rm -rf .next` and `pm2 delete`+`pm2 start` (downtime). | fixed |
| D3 | HIGH | **No rollback / not atomic.** `rsync --delete` overwrites `IXWORLD_DIR` in place; build that fails at runtime leaves no prior version, and mid-rsync the dir is served half-updated. | fixed |
| D4 | MEDIUM | **No post-deploy health check.** "Deployment Successful" printed right after `pm2 start`; needs an HTTP 200 probe on `http://localhost:3002/maps`. | fixed |
| D5 | MEDIUM | **`wait_ready: true` mismatch.** `ecosystem.ixworld.config.cjs` sets `wait_ready`+`listen_timeout: 10000`, but Next.js standalone `server.js` never calls `process.send('ready')` → PM2 waits the full 10s each start. | fixed |
| D6 | LOW | **Lockfile not crash-safe.** `[ -f LOCK ]`+`touch`+`trap EXIT`; a hard kill skips the trap and blocks all future deploys. Use `flock`/PID-liveness. | fixed |
| D7 | LOW | **Unbounded deploy log** (`tee -a`, no rotation). | fixed |
| D8 | LOW | **`rsync --delete data/`** removes any runtime-generated files under destination `data/` each deploy; confirm `data/` is build-time-only. | fixed |

## 5. Overall Health

Architecturally sound — clear modular-monolith layering (lib → hooks → components → orchestration), strong TypeScript coverage, sensible router domain grouping. Debt is concentrated and non-systemic: (a) deploy/build hygiene (D1 is the single most impactful issue), (b) a handful of unindexed/unbounded DB queries, (c) client polling/memoization hot spots, (d) accumulated flag/intelligence duplication and never-finished deprecated-wrapper migrations. All addressable incrementally.

## Remediation log (June 2026)

**Phase 1 — deploy script (DONE, D1–D8):** `scripts/deploy-ixworld.sh` rewritten — saves/restores IxStats `.next` so the maps build no longer clobbers it (D1); `flock` lock (D6); hardlink snapshot + health-gated auto-rollback (D3/D4); `pm2 startOrReload` instead of delete/start (D2); log rotation (D7); `data/` synced without `--delete` (D8). `ecosystem.ixworld.config.cjs`: removed `wait_ready`/`listen_timeout` from the ixworld app (D5).

**Phase 2 — DB/backend (DONE B1–B3,B5,B6; B4 wontfix):**
- B1: added `@@index([target, action, timestamp])` to `AuditLog`. ⚠️ **Needs `prisma migrate dev --name add_auditlog_target_index` run in an env with `DATABASE_URL`** — schema + client updated, migration not yet applied.
- B2: `getAutosaveStats` now uses `groupBy`/`_count` + a single `findFirst` instead of loading all rows and scanning 4×.
- B3: cultural-exchange mission creation → `createMany` (both `diplomacy/cultural.ts` and `diplomatic.ts`).
- B5: 5 bulk wiki endpoints converted from sequential `for…await` to `Promise.all` (matching `getBulkWikiIntros`). The per-call `ixwiki ?? iiwiki` short-circuit was kept deliberately (parallelizing it would double external wiki load).
- B6: 4 hot-path `console.log`s in `diplomatic.ts` guarded behind `NODE_ENV !== "production"`.
- **B4 wontfix:** `countries.getAll` genuinely consumes `centroid`/`boundingBox` (transformed into map `bounds`) and the economic fields feed the dashboard — not dead over-fetch. Caching is handled by F2 instead.

**Phase 3 — frontend (DONE F1,F2,F4,F6,F7; F3 dead-code; F5/F8/F9 open):**
- F1: `SecureCommunications` polling queries got `refetchIntervalInBackground:false` + `refetchOnWindowFocus:false`.
- F2: `EnhancedCommandCenter` `getAll`/`getGlobalStats` got `refetchOnWindowFocus:false` + staleTime/gcTime caching.
- F4: 4 military-equipment chart transforms hoisted into `useMemo` above the early returns.
- F6: `SplashHero` 1s clock pauses on tab-hidden via `visibilitychange`. (`DataMonitoringCenter` validated — already gated on `isVisible`.)
- F7: raw flag/COA `<img>` tags got `loading="lazy"`/`decoding="async"` (next/image skipped — external flag hosts not all in remotePatterns).
- **F3:** `bot-monitoring.tsx` (580 LOC, pulled in all of Recharts) was **unused** → deleted.
- **Open:** F5 (memo giant components), F8 (activity waterfall), F9 (provider nesting) — deferred, validate before changing.

**Phase 4 — dead/bloat (mechanical DONE):**
- Untracked accidental `prisma/prisma/dev.db` (`git rm --cached`; already matches the `prisma/**/*.db` ignore rule).
- Deleted superseded code scratch: `geo.ts.bak`, `scripts/geojson_fixed/icecaps.geojson.bak`.
- Removed unused deps `@lmstudio/sdk`, `quansync` from `package.json` (reinstall lockfile to prune).
- ⚠️ **DB backups left in place** (`prisma/prod-backup-*.db`, `prod-sync-copy.db`, `prisma/backups/*` — ~25MB): not deleted; review and remove manually if obsolete.

**Phase 5 — deprecated wrappers (IN PROGRESS):**
- ✅ `animated-number.tsx` deleted — 3 consumers (`ExpandableStatCard`, `health-ring`, `InteractiveMetric`) migrated to `NumberFlowDisplay` (`decimals`→`decimalPlaces`).
- ⏸ `SimpleFlag` (×18) — **NOT a safe mechanical swap.** `SimpleFlag` uses `object-cover` + fixed widths (`w-6/8/12`); `UnifiedCountryFlag` hardcodes `object-contain` + `w-auto`. Inline consumers (feed/cards/dynamic-island) are fine; the flag-grid/rubiks-cube/waving-flag visualizers depend on fixed dimensions and need per-file layout work + visual QA. Recommend migrating as a reviewed change, not a blind batch.
- ✅ `useFlag` (3 consumers → `useUnifiedFlags`) deleted. ⏸ economy `utils.ts` format wrappers, `economic-data-templates`, `parse-provinces` — pending.

**TAX_SYSTEM_TEMP_DISABLED — investigated (LEAVE AS-IS):** Clean, well-documented temporary flag wired through 4 files (`BuilderNotchBar`, `BuilderSidebarNav`, `EconomyBuilderPage`, `useBuilderActions`), with in-UI re-enable instructions. Re-enabling is a one-line change (`= false`), BUT 3 of those 4 files are in the user's current uncommitted changes → the tax system is intentionally disabled during active rework. Not changed.

**Phase 5 — large refactors (NOT started — recommend focused, individually-verified passes):**
- `RealTimeDataService`/`useDataSync` disabled polling — re-enable-with-guards vs delete.
- Flag-lib (9) / intelligence-hook (7) consolidation; giant-component splits (`MyCountryTabSystem` 3,048, etc.); static-data → DB. These are design-level refactors with real regression risk; best done one at a time with typecheck/visual verification.
