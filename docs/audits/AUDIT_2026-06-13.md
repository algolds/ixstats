## Executive summary

A pre-1.0.6 audit revealed three classes of problem that violated the spirit of `arch.md` ("no god files / no cross-router imports / no shared mega-types"):

1. **~50 router files over 700 lines** ("god files")
2. **1 live cross-router import** (`countries/*` → `geo/core`)
3. **1 dead mega-type file** (`src/types/unified-intelligence.ts`, 1,552 lines, 0 importers)

All three were resolved in a 3-wave incremental refactor (44+ router splits across 1,376 procedures, 0 call-site changes), plus a permanent **architecture guard** was added to prevent regression.

## The architecture guard

**File:** `scripts/audit/audit-arch.ts`
**Invocation:** `bun run audit:arch` / `bun run audit:arch:update`

The guard enforces two rules that map directly to `arch.md`:

1. **File-size ceiling (ratcheted).** Every file in `src/server/api/routers/**` and `src/types/**` must be ≤ **700 lines** (default) or ≤ **900 lines** (relaxed for designated core type/data tables). The baseline `arch-baseline.json` records current offenders at their exact line count; new files must be under the ceiling, and ratcheted files may not grow.
2. **No cross-router imports.** No router in `routers/<A>/` may import from `routers/<B>/`. Shared primitives that legitimately need to be cross-router belong in `src/server/shared/`.

The guard is wired into the pre-commit hook and the CI gate via `bun run audit:arch`.

## The canonical splitter

**File:** `scripts/split-router-template.ts`

A single, well-documented tool (~250 lines) that encapsulates the proven recipe for splitting a large flat tRPC router into a same-named subdirectory. The template's 100+ line header comment documents the 6 lessons learned during the refactor:

1. Relative imports break when the file moves one level deeper — `from "./foo"` becomes `from "../foo"`. Pre-flight scan + automatic rewrite is built in.
2. **Dynamic imports too** — `await import("./foo")` has the same problem. The template handles both.
3. **Helper re-exports** — when a router's helper is imported by another router (e.g. `intelligence/alerts/evaluateThresholds` from `intelligence/core/dashboard`), the new `index.ts` must re-export the helper. Without this, external importers break.
4. **Cross-router sharing exception** — the one allowed exception to the no-cross-router rule: a helper used by N routers re-exported from the helper-owner's `index.ts`. Genuinely cross-cutting primitives go in `src/server/shared/`.
5. **AST parity is mandatory** — line-grep counts miss procedures defined via spread, dynamic `Object.assign`, etc. The template has ts-morph parity verification built in (no separate verifier script needed).
6. **Memory safety** — agents that run the splitter must NOT run `tsc --noEmit` (8GB servers OOM). The orchestrator runs one consolidated `bun run typecheck:trpc` after all parallel splits land.

```bash
bun run scripts/split-router-template.ts \
  --routerFile="src/server/api/routers/foo.ts" \
  --outDir="src/server/api/routers/foo" \
  --varName="fooRouter" \
  --groups='{read:["getX","getY"],mutate:["createZ","updateW"]}' \
  --pattern="mergeRouters"
```

The 95+ one-off splitter scripts from the refactor were deleted and replaced by this single canonical tool.

## Issues found and fixed during the refactor

The refactor surfaced a class of bug that the splitter template now prevents by construction: **relative imports that break when a file moves into a subdirectory**.

Pattern: when `routers/foo.ts` is converted to `routers/foo/`, the `from "./bar"` inside the file now resolves to `routers/foo/bar` (which doesn't exist) instead of the original `routers/bar`. Static `import` statements and dynamic `await import()` calls both need rewriting.

The following were caught in real time (before declaring done):

| File | Broken import | Fix |
|---|---|---|
| `wikios/*.ts` (7 sub-files) | `from "./wiki"` | `from "../wiki"` |
| `intelligence/alerts/*.ts` (4 sub-files) | `from "../../schemas/intelligence"` | `from "../../../schemas/intelligence"` |
| `intelligence/analytics/*.ts` (3 sub-files) | same | same |
| `geo/admin.ts` | `from "./core"` | `from "../core"` |
| `geo/features.ts` | same | same |
| `transport.ts` | `from "./geo/features"` | `from "../geo/features"` |
| `ns-import.ts` | `from "../trpc"` | `from "~/server/api/trpc"` (absolute) |
| `countries/management/lifecycle.ts` | `await import("../intelligence/alerts")` | `await import("../../intelligence/alerts")` (the **only** dynamic import bug; `sed` couldn't fix it, needed `perl`) |

The splitter template's pre-flight now checks BOTH `grep -nE "from ['\"]\.\.?/[^'\"]+['\"]"` (static) and `grep -nE "await import\(['\"]\.\.?/[^'\"]+['\"]\)"` (dynamic) and bakes the rewrites into the copy-whole-file step.

## Verification

Every split was independently verified by:

1. **Agent's own AST parity check** (mandatory step 10 in the splitter template) — uses ts-morph to walk `createTRPCRouter({...})` properties and compare the union across new sub-files vs. the original monolith. Reports: `orig=N new=M missing=[] extra=[] dups=[]`.
2. **Orchestrator's independent AST walk** — separate ts-morph script at `_w<N>_verify.cjs` (in /tmp) walking the new subdir recursively and comparing against the original procedure-key set captured from `git show HEAD:<file>.ts` *before* the file was deleted.
3. **Consolidated `bun run typecheck:trpc`** — runs after all parallel splits in a wave land. Catches any broken relative import that slipped past pre-flight. The only errors observed across all 52 splits were:
   - `wikios` wave 1's `./wiki` import (fixed via 7-file sed pass)
   - `countries/management/lifecycle.ts` dynamic import (fixed via perl)
4. **`bun run audit:arch`** — the ratcheting guard, which would have caught any new god file or cross-router import that escaped verification.

All checks passed for all 44+ splits.

## Pre-existing infrastructure this work leveraged

The refactor was possible only because of prior work:

- **`split-activities-ast.ts`** (Phase 1 — June 2026) — the proven AST splitter template
- **`mergeRouters`** from `~/server/api/trpc` (since 11.17) — recombines sub-routers into the parent
- **`scripts/verify-router-splits.ts`** (pre-existing) — independent AST parity checker for the 4 first split routers
- **Memory-safe orchestration** — agents that run the splitter do NOT run `tsc --noEmit`; the orchestrator runs ONE consolidated typecheck after all parallel splits in a wave land. 8GB server can't sustain concurrent 6GB typechecks.

## What this audit does NOT cover

- **Service-layer extraction** (`arch.md` §5 forbids routers from doing DB queries inline; currently 116/135 routers do). This is a larger, multi-month refactor outside this audit's scope. The arch guard does not enforce it.
- **Full `tsc --noEmit`** — the 8GB dev server can typecheck sub-projects (ui, server, trpc, db) sequentially with `--max-old-space-size=6144`/`4096` heap bounds, but cannot run a full typecheck. `bun run typecheck` chains all 4 sub-projects sequentially.
- **Regenerating `docs/reference/api-complete.md`** — the per-router procedure counts and per-section totals in the file are pre-1.0.6; the header now warns that regeneration is needed. A script could be added to `scripts/audit/` to do this from the live tree if desired.
