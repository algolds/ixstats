# Research Spike Decision Document: Sports LLM Commentary

This document summarizes the research and recommendations for integrating LLM-generated play-by-play match commentary into the IxStates sports engine.

## Executive Summary
We recommend a **GO** decision on integrating sports LLM commentary, using **OpenAI's GPT-4o-Mini** or **OpenRouter Llama 3.1 70B** as the primary engines, with a strict **asynchronous, post-resolution, flag-gated narration architecture** that preserves match determinism and ensures simulation safety.

## Recommended Architecture

To satisfy the **Hard Invariant (Outcome Determinism)**:
1. **Outcome Isolation**: The LLM must have **zero influence** over the match outcome. The simulation must run fully deterministically (relying on mulberry32 seeded RNG).
2. **Async Enrichment**: Narration happens *after* the match is completely resolved. The event trace generated by the simulator is passed to the narration worker.
3. **Structured Caching**: Narration outputs must be cached using `(matchId, seed)` as the key. This ensures that the generated narration is itself reproducible and cached, preventing redundant API calls.
4. **Best-Effort with Graceful Fallback**: If the LLM call fails, times out, or returns invalid JSON/length mismatch, the system must immediately and silently fall back to the pre-existing templated event descriptions. The user's simulation is never blocked or aborted.
