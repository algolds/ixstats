## Why this matters

The sim is silent: results only appear if you open the league page. The owner
wants an ESPN-style living feed. There's already a feed bot (`SportsNews`
ThinkPages account) and an established auto-post pattern used at season
transitions — but **per-match-day results are never posted**. This plan fires a
results bulletin to `SportsNews` after a match day is simulated, so the public
ThinkPages feed reflects league action in near-real-time. To avoid spam, it posts
a **single digest per match day** (not one post per match) and is best-effort
(a feed failure must never fail the simulation).

## Steps

### Step 1: Pure bulletin formatter (testable)

Create `src/lib/sports/feed-bulletins.ts` — turns a match-day result set into a
single post body. Keep it pure (no DB, no IxTime). Include an "upset" marker when
the lower-seeded/under-rated side wins if that signal is available; otherwise
just list scores. Keep it concise (feed-friendly).

```ts
export interface MatchDayResultLine {
  homeName: string;
  awayName: string;
  homeScore: number;
  awayScore: number;
}

export function formatMatchDayBulletin(args: {
  leagueName: string;
  sportEmoji: string;
  matchDay: number;
  results: MatchDayResultLine[];
}): string {
  const { leagueName, sportEmoji, matchDay, results } = args;
  const lines = results.map(
    (r) => `${r.homeName} ${r.homeScore}–${r.awayScore} ${r.awayName}`
  );
  return `${sportEmoji} [${leagueName}] Match Day ${matchDay} results\n\n${lines.join("\n")}`;
}
```

### Step 3: Post the bulletin after a match day resolves

In `simulateMatchDay` (`matches.ts`), after the results array is fully built and
the match rows are persisted, build the `MatchDayResultLine[]` from the resolved
results (map the resolver's score/team fields — confirm exact names by reading
the result push around lines 290–360), then post best-effort:

```ts
// Best-effort feed bulletin — must never fail the simulation
try {
  const acct = await ctx.db.thinkpagesAccount.findUnique({ where: { username: "SportsNews" } });
  if (acct) {
    const { getSportEmoji } = await import("~/lib/sports/presets");
    const { formatMatchDayBulletin } = await import("~/lib/sports/feed-bulletins");
    const { IxTime } = await import("~/lib/ixtime");
    const content = formatMatchDayBulletin({
      leagueName: season.league.name,
      sportEmoji: getSportEmoji(season.league.sportPreset),
      matchDay: input.matchDay,
      results: resultLines,   // built from the resolved results
    });
    await ctx.db.thinkpagesPost.create({
      data: {
        accountId: acct.id,
        content,
        isAutoGenerated: true,
        ixTimeTimestamp: IxTime.timestampToDate(IxTime.getCurrentIxTime()),
      },
    });
  }
} catch (err) {
  console.error("[simulateMatchDay] feed bulletin failed:", err);
}
```

Place this **after** the existing DB writes and **before** the mutation returns,
outside any transaction whose failure should roll back the sim (the post is
non-critical). Match how `transition.ts` imports `IxTime` (use the same path).
